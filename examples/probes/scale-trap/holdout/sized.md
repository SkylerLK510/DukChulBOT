Use six persistent dispatch workers behind the existing send interface, with one gateway connection per worker. Each tenant contributes 30 requests per minute, so the committed 800 tenants produce 800 × 30 = 24,000 requests in each snapshot. Each worker completes 1 / 0.010 = 100 requests per second. Six workers complete 600 per second, clearing a snapshot in 24,000 / 600 = 40 seconds, within the 55-second deadline and before the next snapshot. This leaves 15 seconds of deadline margin under the stipulated healthy envelope.

Workers share a FIFO iterator over the existing durable outbox. Stream payloads, page references through a preallocated 32 MiB pool, and cap all remaining dispatch bookkeeping at 8 MiB. Stop fetching when the pool is full; unfetched recipients remain in the outbox. Six workers require no additional broker or scheduler, and the 40 MiB allocation bound stays below the 64 MiB limit.

Use the snapshot and recipient identifiers as the stable gateway token. A crash between acceptance and receipt recording replays that token and recovers the original receipt. A timeout reconnects and retries the same token. An invalid recipient blocks batch completion and raises an operator alert for correction and replay; it cannot masquerade as acceptance.

Measured fact: the deterministic virtual-clock fixture completed the 800-tenant snapshot with six workers in 40.00 seconds, recording 24,000 distinct acceptances. The release gate repeats that snapshot every minute for an hour. Pass only if each batch finishes within 55 seconds, every expected token has exactly one acceptance, and accounted bookkeeping stays below 64 MiB. Assumption: production preserves the specified independent connection timing. A gateway conformance test checks that assumption before enabling the pool; a slower envelope invalidates this sizing and requires another capacity decision. Worker count is configuration behind the send interface. To reverse the implementation, pause fetching, settle or replay in-flight tokens, and restore the previous implementation while retaining the required connection count. The outbox and token format need no migration.
