Use two persistent dispatch workers behind the existing send interface. Each worker owns one gateway connection and sends one recipient request at a time. A request occupies that worker for 10 milliseconds, including acknowledgement. Each tenant contributes 30 recipient requests per minute. Workers share a FIFO iterator over the durable outbox, so neither a separate broker nor a scheduler service is needed. Keep the pool fixed at two workers.

The iterator streams payloads and pages recipient references through a preallocated 32 MiB bookkeeping pool. Worker state and iterator overhead have a separate 8 MiB allocation cap. When the pool fills, stop fetching references; leave the remaining records in the outbox. Release a reference after recording its receipt. This bounds resident bookkeeping without discarding recipients.

Give every request a stable token derived from the snapshot identifier and recipient identifier. If the process dies after gateway acceptance but before receipt recording, replay the same token and record the original receipt. If a connection times out, reconnect and retry that token before advancing its worker. An invalid recipient is recorded as a terminal error and blocks release of the batch, with an operator alert to correct and replay that record. It is never silently counted as accepted.

Measured fact: the deterministic acceptance fixture, using the stipulated gateway timing and a virtual clock, completed a 100-tenant replay with 3,000 distinct acceptances in 15.00 seconds. The release test repeats this replay every minute for an hour; pass only if every batch finishes within 55 seconds, has exactly its expected recipient tokens, and stays below 64 MiB of accounted bookkeeping allocations. Kill the dispatcher after acceptance but before recording a receipt; pass only if restart produces one acceptance and a recorded receipt for that token. Inject a timeout and an invalid recipient to check replay and the blocking alert.

Assumption: the implementation preserves the fixture's connection independence and timing. Run a gateway conformance check before release; a different timing envelope reopens the worker choice. The send interface, outbox schema, and token format remain unchanged. Pause fetching, finish or replay outstanding tokens, and swap the worker implementation or worker-count setting at that interface to undo this choice.
